# Material origins and notices

The repository owner identifies the original Channels DVR EPG/prototype as their
own Kodi add-on development project on Windows, before this GitHub repository
was created. The public Hub history begins at source import
`9c966f10ce41338d4bb050b328b792695eede9ae`; it does not preserve the earlier
Windows development history. No earlier checkout or repository was supplied.
The current source and bundled license retain the MIT grant and prototype
contributor notice. This statement does not reconstruct missing history or
claim that Git authorship alone proves every possible third-party right.

The 0.1.2 preparation review inspected the runtime inventory, imports, code and
notices. No vendored provider application, SDK, font, binary or media library
was identified. Comparisons with the owner's earlier `script.epg_fuzzy_match`
and `channels-plex-agent` repository snapshots identified no copied file or
substantive matching code block; that bounded comparison is not a universal
originality search. Python's standard library and Kodi APIs are runtime
dependencies, not bundled third-party libraries.

The original icon and four skin textures entered with the initial Hub import.
They are simple geometric/solid-colour PNGs without embedded creator or source
metadata. Their earlier generation history could not be established. To avoid
depending on that uncertain artwork history, **0.1.2 replaces all five** with
original geometric artwork specified in `tools/generate_artwork.py`, under the
project's MIT terms. The generator uses only solid RGB colours and rectangles;
it downloads nothing and consumes no images, logos, fonts or external design
files. Run `python3 -B tools/generate_artwork.py --check` to verify the exact
generated bytes in the build environment. Python/zlib versions affect compressed
PNG bytes; the release's file hashes bind the shipped outputs.

Frozen 0.1.1 and earlier packages, artwork and evidence are unchanged. The new
artwork and notice do not establish native acceptance. Channels and Fancy Bits
remain third-party names used to identify the configured backend; no affiliation,
endorsement, provider permission or content authorization is claimed. Runtime
metadata/artwork/streams require the user's own authorization and entitlements.
